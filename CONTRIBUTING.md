Thank you for considering contributing to this project! This template helps thousands of creators automate their LinkedIn content while maintaining quality and authenticity.

- Found something that doesn't work?
- Have a fix to suggest?
- Want to improve existing code?

## 📋 Contribution Guidelines

### Before Contributing

**1. Check if it already exists:**
- Search GitHub Issues
- Check GitHub Discussions
- Review existing PRs

**2. Understand the philosophy:**

This system is built on these principles:
- ✅ Quality over quantity
- ✅ Authenticity over automation
- ✅ Simplicity over complexity
- ✅ Open source over proprietary
- ✅ Community over individual

**Contributions should align with these values.**

### Contribution Standards

**Documentation:**
- Clear and concise
- Include examples
- Assume beginner audience
- No jargon without explanation
- Markdown formatting

**Templates:**
- Follow existing structure
- Include clear instructions
- Provide examples
- Explain use case
- Credit any sources

**Code/Scripts:**
- Well commented
- Follow existing patterns
- Include README
- Tested and working
- Cross-platform when possible

**Prompts:**
- Tested with at least 2 AI tools (Claude, ChatGPT)
- Include examples of output
- Explain customization points
- Clear instructions

## 🔧 How to Contribute

### Small Changes (Typos, Small Fixes)

**Process:**
1. Fork the repository
2. Make your changes
3. Submit a Pull Request
4. Describe what you changed and why

**We'll review and merge quickly.**

### Medium Changes (New Templates, Docs)

**Process:**
1. Open an Issue first describing what you want to add
2. Wait for feedback/approval
3. Fork the repository
4. Create your content
5. Submit a Pull Request
6. Reference the original Issue

**Why Issue first?**
- Avoids duplicate work
- Ensures alignment with project goals
- Gets feedback early

### Large Changes (New Features, Major Rewrites)

**Process:**
1. Open a GitHub Discussion
2. Describe the proposed change
3. Explain the value and use case
4. Get community feedback
5. If approved, open an Issue
6. Work on the feature
7. Submit Pull Request with thorough documentation

**Examples of large changes:**
- New workflow entirely
- Major restructuring
- Integration with external tools
- Significant prompt rewrites

## 📝 Pull Request Guidelines

### PR Title Format

Use conventional commit format:

```
feat: Add carousel post template
fix: Correct typo in SETUP.md
docs: Improve brand voice examples
chore: Update .gitignore
```

**Types:**
- `feat`: New feature/template
- `fix`: Bug fix or correction
- `docs`: Documentation changes
- `chore`: Maintenance tasks
- `refactor`: Code/structure improvements

### PR Description Template

```markdown
## What does this PR do?

[Brief description of changes]

## Why is this needed?

[Explain the problem this solves]

## How has this been tested?

[Describe how you tested this]

## Screenshots (if applicable)

[Add screenshots if visual changes]

## Checklist

- [ ] Documentation updated
- [ ] Examples added
- [ ] Tested and working
- [ ] Follows project style
- [ ] No breaking changes (or documented if yes)
```

### Review Process

**Timeline:**
- Small changes: 1-3 days
- Medium changes: 3-7 days
- Large changes: 1-2 weeks

**What we look for:**
- Alignment with project goals
- Quality of implementation
- Completeness of documentation
- Testing/validation
- No breaking changes (or properly documented)

## 🎨 Style Guidelines

### Documentation Style

**Tone:**
- Conversational but professional
- Direct and actionable
- Encouraging and supportive
- No corporate jargon

**Structure:**
- Clear headings (H2, H3)
- Short paragraphs (3-5 lines max)
- Bullet points for lists
- Code blocks for examples
- Emojis for visual scanning (but not excessive)

**Example:**

```markdown
## 🎯 How to Do X

Brief introduction to the concept.

**Step 1: Do this**
- Point 1
- Point 2

**Step 2: Then this**
```

**Example of good vs. bad:**

**❌ Bad:**
```
Utilize the aforementioned methodology to facilitate the implementation
of your content automation infrastructure.
```

**✅ Good:**
```
Use this method to set up your content automation system.
```

### Template Style

**All templates should include:**

1. **Header with title and purpose**
2. **Structure/outline**
3. **Example(s)**
4. **Customization instructions**
5. **Use case explanation**

**Example:**

```markdown
# [Template Name]

**Purpose:** [What this template is for]
**Use case:** [When to use it]

## Structure:

[Outline of the template structure]

## Example:

[Full example of completed template]

## Customization:

[How to adapt to your needs]
```

### Prompt Style

**All prompts should include:**

1. **Context (who you are, what you do)**
2. **Input (what you're providing)**
3. **Output format (what you want)**
4. **Examples (show, don't just tell)**
5. **Constraints (what to avoid)**

## ❌ What We Won't Accept

**Spam or Low-Quality:**
- AI-generated PRs without human review
- Untested changes
- Incomplete documentation
- Copy-paste from other sources without attribution

**Off-Brand:**
- Promotes paid tools exclusively
- Adds unnecessary complexity
- Violates open source principles
- Includes affiliate links without disclosure

**Harmful:**
- Spammy automation techniques
- Violates LinkedIn ToS
- Unethical practices
- Plagiarism

**Breaking Changes:**
- Major restructuring without discussion
- Removes existing functionality
- Changes core philosophy
- No backward compatibility (without very good reason)
